# «Остатки», учебное приложение курса Хекслета «Фронтенд в продакшене»

[![Check](https://github.com/hexlet-components/warehouse-stock/actions/workflows/check.yml/badge.svg)](https://github.com/hexlet-components/warehouse-stock/actions/workflows/check.yml)

</div>

Компонент создаёт и поддерживает команда [Хекслета](https://hexlet.io/?utm_source=github&utm_medium=link&utm_campaign=warehouse-stock), образовательного проекта.

«Остатки» это учебное приложение курса «Фронтенд в продакшене» из [каталога Хекслета](https://ru.hexlet.io/courses?utm_source=github&utm_medium=link&utm_campaign=warehouse-stock). На нём сняты примеры уроков, от вывода сборки и ответов сервера до выпуска новой версии и отката. Приложение нужно, чтобы повторить эти примеры у себя и сломать то же, что ломается в уроках. Интерфейс написан на обычном JavaScript и DOM, сборку выполняет Vite. React и TypeScript для работы с примером не требуются.

[Демо на GitHub Pages](https://hexlet-components.github.io/warehouse-stock/) показывает интерфейс без установки. В демо API и конфиг работают прямо в браузере, а остатки хранятся в `localStorage`, поэтому публикация, кеш и CORS из уроков там не воспроизводятся.

Приложение ведёт учёт товаров на складе магазина. Сотрудники видят список товаров с остатками, а на карточке товара, например `/products/42`, принимают и выдают товар в выбранном количестве. Менеджер смотрит движение товаров в разделе `/reports`, его код загружается отдельным чанком. Ролей нет, все разделы открыты всем. На карточке товара сотрудник проверяет штрихкод с упаковки перед приёмом или выдачей. В проверке оставлена настоящая ошибка для уроков о диагностике: у молока штрихкод ещё не заведён, и на его карточке `/products/42` проверка падает с `TypeError`. Сотрудник видит сообщение о сбое, а ошибка через `reportError` попадает в Console и в системы мониторинга. API хранит остатки и движения в памяти, поэтому после перезапуска они возвращаются к исходным. Источники приложения находятся в _src/_, серверы и команды публикации в _server/_, данные товаров в _data/products.json_, статический файл _public/robots.txt_ копируется в результат без хеша.

## Запуск

Нужен Node.js 26 или новее, он ставится по [инструкции Хекслета](https://github.com/Hexlet/ru-instructions/blob/main/nodejs.md). Склонируйте репозиторий или создайте свою копию кнопкой **Use this template** и выполняйте команды из его каталога.

```bash
npm ci
npm start
```

Состояние публикаций хранится в _.state/_. Команда `npm run reset` удаляет его вместе с _dist/_ и _published/_ и возвращает приложение к состоянию после клонирования, поэтому выпуски можно публиковать заново. Запускайте её при остановленных серверах.

Серверы приложения остаются работать в отдельном терминале. Они предоставляют раздачу опубликованного приложения на `http://127.0.0.1:8080`, готовый API на `http://127.0.0.1:8081` и модель общего кеша на `http://127.0.0.1:8082`. Локальный кеш показывает хранение ответов; географической доставки у него нет.

Во втором терминале приложение можно открыть через dev-сервер.

```bash
npm run dev
```

Dev-сервер работает на `http://127.0.0.1:5173`. Команда `npm run preview` после сборки открывает результат на `http://127.0.0.1:4173`. Обоим нужен работающий API приложения; предварительная публикация не требуется. Vite предоставляет публичный _app-config.json_ из этого каталога отдельно от файлов сборки. Правка этого JSON видна после перезагрузки страницы без пересборки.

## Сборка и публикация

```bash
RELEASE_ID=A npm run build
npm run manifest
npm run publish -- A
npm run activate -- A
```

Сборка содержит _release.json_ с версией и _assets/_ с хешированными ресурсами. Команда публикации сохраняет байты _dist/_ в _.state/releases/A/_, контрольные суммы в _.state/manifests/A.json_ и копирует ресурсы в _.state/shared/assets/_. Существующий релиз перезаписать нельзя. Активация сверяет сохранённые файлы с контрольными суммами и выбирает релиз; новой сборки она не делает.

Публикация копирует отдельный _app-config.json_ в _.state/configs/A.json_. Этот конфиг не находится в _public/_ и не входит в _dist/_. Менять параметры опубликованного окружения можно независимо от сборки.

```bash
npm run configure -- environment staging
npm run configure -- apiBase http://127.0.0.1:8081/api
```

После перезагрузки браузер получает новый конфиг. Прямой запрос к API на другом порту позволяет наблюдать CORS. Значение `/api` возвращает запросы на адрес самого приложения, где сервер приложения пересылает их в API.

## Управляемые поломки

Настройки сохраняются в _.state/settings.json_. По умолчанию fallback и CORS включены, длительное кеширование HTML выключено.

```bash
npm run configure -- fallback false
npm run configure -- cors false
npm run configure -- cacheHtml true
npm run invalidate
```

Fallback применяется к запросу HTML по маршруту без расширения. Отсутствующие ресурсы возвращают 404. Хешированные ресурсы получают длительную политику хранения. HTML и runtime-конфиг по умолчанию требуют повторной проверки. `cacheHtml true` намеренно делает HTML свежим в течение часа; через адрес общего кеша можно увидеть старую версию. Учебный заголовок `X-Cache` принимает значения `MISS`, `HIT` и `BYPASS`. Инвалидация очищает только модель общего кеша, отдельный кеш браузера она не меняет.

Выпуск B сохраняет файлы A для открытых вкладок. Чанк отчёта A можно удалить командой ниже, подставив фактическое имя из манифеста A.

```bash
npm run remove-asset -- assets/reports-ИМЯ.js
```

Команда удаляет файл только из общей раздачи. Копия в _.state/releases/A/assets/_ остаётся для исследования и восстановления. Для отката достаточно `npm run activate -- A`, если старые ресурсы доступны. После удаления ресурса его нужно вернуть из сохранённого комплекта. Инвалидация не восстанавливает отсутствующие файлы.

## Карты и проверки

```bash
RELEASE_ID=C SOURCEMAP=true npm run build
npm test
```

Карты создаются рядом с JavaScript. Для публичного комплекта без карт их нужно отделить до публикации. Интеграции с живым Sentry в этом примере нет.

Проверка собирает реальные версии A и B во временном каталоге, проверяет неизменность публикации, fallback, 404 ресурса, CORS, попадание в общий кеш и его сброс, сохранение старого чанка, runtime-конфигурацию, откат и отказ активации изменённого комплекта. Тесты используют свободные локальные порты и удаляют только свой временный каталог.

## Проверки

Для поддержки приложения.

```sh
mise run setup
mise run test
mise run check
```

`mise run check` гоняет тот же набор, что CI: разметку, опечатки, ссылки, workflows, oxlint и oxfmt, уязвимости зависимостей. `make <задача>` вызывает ту же задачу mise.
